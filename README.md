# Лабораторная работа №1 — транзакционная память

Мобильное приложение на **.NET MAUI**, которое показывает в реальном времени,
как работает транзакционная память и чем оптимистичный подход (CAS / STM)
отличается от пессимистичного (блокировки) и от варианта без синхронизации.

Два примера из задания — два режима одной программы:

* **Пример 1** — механизм STM на чистом CAS: потоки пополняют один счёт, каждая
  попытка подтверждается `Interlocked.CompareExchange`, потерянных пополнений нет
  ни при каком числе потоков;
* **Пример 2** — транзакции над несколькими объектами: переводы между счетами
  внутри `TxContext.Execute`; при конфликте версий транзакция целиком
  откатывается и переигрывается, поэтому сумма денег на счетах неизменна.

Рядом для сравнения: **Блокировки** (пессимистичный подход) и **Без
синхронизации** — специально сломанный режим, который показывает потерю денег.

## Запуск

```powershell
cd maui\TmLab
dotnet build -f net10.0-windows10.0.19041.0
```

Проще всего — открыть `maui/TmLab.sln` в Visual Studio, выбрать устройство
**Windows Machine** и нажать **F5**. Подробности (в том числе как собрать под
Android и что делать, если мало места на диске) — в `maui/README.md`.

## Как устроено

* `Models/Account.cs` — счёт: значение, версия данных, замок, `TryCompareExchange`
  (Пример 1) и согласованное чтение пары «значение + версия» (seqlock).
* `Models/TxContext.cs` — мини-STM: журнал чтения/записи, валидация версий,
  фиксация под общим замком, откат и повтор всей транзакции (Пример 2).
* `Simulation/SimulationRunner.cs` — настоящие потоки (`Task`) и четыре сценария:
  CAS-цикл, STM, блокировки, без синхронизации.
* `Drawing/` — схема с летящими монетками и таймлайн фаз транзакции на `IDrawable`.
* `Views/MainPage.xaml` — экран: адаптивная раскладка, схема ~40–50 % высоты,
  компактные показатели, строка инварианта, панели «Потоки / Таймлайн / Журнал».
