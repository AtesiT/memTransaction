# Лабораторная работа №1 — транзакционная память

Практическая часть работы сделана в двух вариантах, которые показывают один и
тот же алгоритм:

| Папка | Что это | Как запустить |
|---|---|---|
| `web/` | веб-стенд: настоящие потоки (Web Worker + `SharedArrayBuffer` + `Atomics`), либо детерминированный симулятор планировщика | `cd web && node server.js` → http://localhost:8080 |
| `maui/` | мобильное приложение .NET MAUI: потоки `Task`, `Interlocked.CompareExchange`, транзакции на `TxContext` | `maui/TmLab.sln` в Visual Studio, либо `dotnet build -f net9.0-android` |

Обе версии демонстрируют два примера из задания:

* **Пример 1** — транзакционная память на чистом CAS: зачисления на один счёт,
  потерянных пополнений нет ни при каком числе потоков;
* **Пример 2** — транзакции над несколькими объектами: переводы между счетами,
  при конфликте версий транзакция целиком откатывается и переигрывается, поэтому
  сумма денег на счетах неизменна (кроме специально сломанного режима
  «без синхронизации» — он нужен для сравнения).

Документы:

* `web/README.md` — как устроен веб-стенд, режимы исполнения, тесты;
* `web/docs/zashchita.md` — сценарий показа и вопросы с ответами;
* `web/docs/csharp-tm.md` — листинги на C# по ходу работы;
* `web/docs/maui-plan.md` — как экран веб-стенда переносится на мобильную вёрстку;
* `maui/README.md` — сборка приложения MAUI, состав проекта, что где искать.

Тесты веб-стенда:

```bash
cd web
node tests/tm.test.js        # алгоритм: параллельные переводы, конфликты, инвариант
node tests/network.test.js   # отрисовка схемы
node tests/ui-smoke.js       # сборка страницы и мобильная раскладка
```
