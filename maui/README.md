# Транзакционная память — мобильное приложение .NET MAUI

Лабораторная работа №1. Мобильное приложение делает то же, что веб-стенд в
соседней папке `web/`, но на C# и на настоящих потоках процесса: `Task.Run`
вместо Web Worker, `Interlocked.CompareExchange` вместо `Atomics.compareExchange`,
`lock`/`Monitor` вместо мьютекса рабочего потока.

Два примера из задания — два режима одной программы:

| Пример из задания | Что показывает приложение |
|---|---|
| **1. Транзакционная память через CAS** (`Interlocked.CompareExchange`, 100 зачислений по +10) | кнопка **«Пример 1 · зачисление»**: потоки пополняют один счёт; монетка долетает до счёта только тогда, когда CAS прошёл, при конфликте гаснет на полпути |
| **2. Многообъектная транзакция** (`TxContext.Execute`, перевод между счетами) | кнопка **«Пример 2 · переводы»**: живые переводы между четырьмя счетами, откат и повтор транзакции при конфликте версий |

Плюс два режима для сравнения: **Блокировки** (пессимистичный подход) и
**Без синхронизации** (специально сломанный вариант — показывает потерю денег).

## Как запустить на Windows (основной путь)

1. Откройте `maui/TmLab.sln` в Visual Studio.
2. В списке устройств выберите **Windows Machine** и нажмите **F5**.

Проект собирается **без упаковки в MSIX** — как в новом шаблоне MAUI. Поэтому
не нужны ни режим разработчика, ни сертификат подписи, ни отдельно установленная
среда Windows App Runtime: MAUI сама включает `WindowsAppSDKSelfContained` и
кладёт среду рядом с программой.

Сборка из командной строки (без запуска):

```bash
cd maui/TmLab
dotnet build
```

### Два переключателя в `TmLab/TmLab.csproj`

| Переключатель | Значение по умолчанию | Зачем |
|---|---|---|
| `WindowsOnly` | `true` | собирается только Windows-версия, поэтому Visual Studio не просит ставить нагрузки `maui-android`/`maui-ios` и Android SDK с эмулятором (несколько ГБ). Поставьте `false` — вернутся Android, iOS и Mac Catalyst |
| `DotNetVersion` | `10.0` | версия .NET. Возможны `10.0`, `9.0`, `8.0` |

Как выбрать `DotNetVersion`: посмотрите два списка —

```powershell
dotnet --list-sdks      # какие SDK вообще есть на компьютере
dotnet workload list    # для каких версий стоит нагрузка MAUI
```

Нужна версия, которая есть в **обоих** списках: например, SDK `10.0.401`,
а в нагрузках строка `maui-windows 10.0.20/10.0.100` — значит, подходит `10.0`.
Если указать версию, которой на компьютере нет, приложение и покажет то самое
окно «You must install or update .NET», а сборка будет просить доустановить SDK.

### Если рабочей нагрузки MAUI ещё нет

```bash
dotnet workload install maui-windows
```

Это в разы меньше, чем `maui`: ставится только Windows-нагрузка, без Android SDK,
эмулятора и iOS/Mac Catalyst. Проверить, что установлено: `dotnet workload list`.

### Ошибка «has exited with code 2147516566 (0x80008096)»

Это **не ошибка программы**: код `0x80008096` — ответ среды выполнения, когда
приложение не нашло подходящую версию .NET (в англоязычном окне — «You must
install or update .NET to run this application»).

Самая частая причина — в `TmLab.csproj` указана версия, которой на компьютере нет.
Так было и в этом проекте: стояло `9.0`, а установлены SDK `8.0.425` и `10.0.401`.
Теперь по умолчанию `10.0`. Проверьте у себя:

```powershell
dotnet --list-sdks
dotnet workload list
```

и при необходимости поправьте одну строку `<DotNetVersion>` в `TmLab.csproj`.

Если версия на месте, а окно всё равно появляется, есть ещё три способа — от
самого экономного по месту на диске:

1. поставить ровно ту версию .NET, которую просит окно (для запуска достаточно
   **runtime**, а не SDK — загрузка десятки мегабайт);
2. поставить в `TmLab/TmLab.csproj` ту версию, которая уже установлена:
   `<DotNetVersion>8.0</DotNetVersion>` (проверить: `dotnet --list-sdks`);
3. раскомментировать в `TmLab.csproj` свойство `SelfContained` (комментарий рядом
   с ним): тогда приложение понесёт среду .NET с собой и вообще не будет
   зависеть от установленных версий — одноразовая загрузка ~60 МБ в пакетах NuGet.

Предложение Visual Studio «доступно обновление рабочей нагрузки .NET MAUI» можно
спокойно отклонить: для сборки и запуска проекта обновление не требуется.

Если после смены версии остаются ошибки — удалите папки `bin` и `obj` проекта:
в них лежат результаты сборки прежней версии.

### Сообщение «The debug executable ... does not exist»

Значит, сборка не добралась до конца: файла `TmLab.exe` нет там, где его ищет
профиль запуска (он ждёт его в `bin\Debug\net10.0-windows10.0.19041.0\win-x64\`).
Проверяйте по порядку:

1. Откройте окно **Вывод** (View → Output) и найдите строки со словом `error`.
   Самые частые случаи:
   * `NU1xxx`, например «Unable to load the service index for source
     `https://api.nuget.org/v3/index.json`» — компьютер не дотянулся до nuget.org.
     Нужен рабочий доступ к нему (VPN/прокси) — только на время первого
     восстановления пакетов, дальше они берутся из кэша;
   * `CS…`, `XAML…`, `MSB…` — собственно ошибки сборки: пришлите их текст.
2. Удалите `bin`, `obj` и скрытую папку `.vs` — в них часто остаются результаты
   сборки прежних версий (классическая причина именно этого сообщения):

   ```powershell
   cd C:\Users\User\Downloads\memTransaction\maui\TmLab
   Remove-Item -Recurse -Force bin, obj, .vs -ErrorAction SilentlyContinue
   dotnet build -f net10.0-windows10.0.19041.0
   ```

3. Проверьте, появился ли файл:

   ```powershell
   dir /s /b bin\*.exe
   ```

   * файл есть, а Visual Studio всё равно ругается — закройте VS, удалите папку
     `.vs` в корне решения и откройте решение заново (VS держит пути в кэше);
   * файла нет — сборка не завершилась, см. пункт 1.

4. Сборка может сорваться из-за значка: растеризатор SVG в MAUI не любит
   обводки, группы и стили. Значки в этом проекте сведены к простым заливкам,
   но если вы их меняли — верните вариант «только заливки».

**Проще всего:** запустите `maui\build-windows.cmd`. Он сам очищает `bin` и `obj`,
показывает состав установленных SDK и нагрузок, выполняет восстановление и сборку
и сохраняет полный журнал в `maui\build-log.txt` — этот файл можно просто
отправить целиком, ошибка в нём будет видна сразу.

### Что для Windows есть в проекте

| Файл | Зачем |
|---|---|
| `TmLab/Properties/launchSettings.json` | профиль запуска «Windows Machine» (`commandName: Project` — запуск как обычной программы, без MSIX) |
| `TmLab/Platforms/Windows/app.manifest` | манифест приложения (корректная работа с DPI на разных экранах) |
| `TmLab/Platforms/Windows/Package.appxmanifest` | манифест пакета для будущей публикации в Store: заглушки `$placeholder$`, `maui-package-name-placeholder`, `0.0.0.0` MAUI заменяет на заголовок, значки и версию из csproj. В режиме `WindowsPackageType=None` файл просто не используется, но пусть лежит |
| `TmLab.sln` | у проекта есть строки `Deploy.0` в конфигурациях решения — понадобятся при упаковке в MSIX |

Если решение когда-нибудь понадобится упаковать в MSIX (например, для Store):
в csproj ставится `<WindowsPackageType>MSIX</WindowsPackageType>`, а в
`launchSettings.json` — `"commandName": "MsixPackage"`; тогда потребуется режим
разработчика (Visual Studio предложит его включить).

### Мало места на диске C:

Что можно освободить, по убыванию выгоды:

```powershell
# сколько занято и свободно
Get-PSDrive C | Select-Object Used,Free

# 1. Перенести кэш пакетов NuGet на другой диск, старый — очистить
setx NUGET_PACKAGES D:\nuget
setx TEMP D:\Temp
setx TMP  D:\Temp
# после этого открыть новое окно консоли и выполнить:
dotnet nuget locals all --clear
```

2. **Кэш загрузок Visual Studio** (бывает несколько ГБ): Visual Studio Installer →
   «Изменить» → «Размещение установки» → «Кэш загрузок» → другой диск. Сразу
   после установки/обновления его вообще можно удалить:
   `C:\ProgramData\Microsoft\VisualStudio\Packages`.
3. **Образы Android-эмулятора и Android SDK** — если Windows-версии достаточно,
   они не нужны совсем: `%USERPROFILE%\.android\avd`,
   `%LOCALAPPDATA%\Android\Sdk`, `C:\Program Files (x86)\Android\android-sdk`.
4. **Компоненты Android в Visual Studio**: Installer → «Изменить» → у нагрузки
   .NET MAUI снять галочки «Android SDK setup», «Android Emulator»,
   «Intel HAXM» (и «iOS build tools», если iPhone не нужен).
5. **`bin` Windows-версии**: она кладёт рядом с программой среду Windows App SDK
   (около 100 МБ). Если место важнее скорости запуска, поставьте в `TmLab.csproj`
   `<WindowsAppSDKSelfContained>false</WindowsAppSDKSelfContained>` и один раз
   установите **Windows App Runtime** из Microsoft Store.
6. **`%TEMP%`** и «Очистка диска» (`cleanmgr`), плюс удаление папок
   `bin` и `obj` этого проекта: они пересоздаются (`dotnet clean`).
7. Сам проект удобнее держать не в `C:\Users\...\Downloads`, а на диске
   с местом: путь значения не имеет, `bin`/`obj` перестанут занимать C:.

## Что на экране

Сверху вниз — то же, что на веб-стенде в «узкой» раскладке:

1. **Переключатель примера** (Пример 1 / Пример 2).
2. **Параметры запуска** — свёрнуты кнопкой «▸ Параметры запуска»: сценарий
   синхронизации (CAS / STM, Блокировки, Без синхронизации), темп показа
   (показ / обычный / нагрузка), число потоков, «работа в транзакции»
   (аналог `Thread.SpinWait`), пауза между операциями, тумблер разброса времени.
3. **Схема** — главный элемент, занимает около 40 % высоты: счета-участники с
   балансом и версией данных, кружки потоков, летящие монетки и вспышки при
   зачислении. Красная монетка, гаснущая на полпути, — это откат транзакции.
4. **Показатели**: операций, коммитов, откатов (или ожиданий), отказов,
   операций в секунду, эффективность (доля успешных попыток).
5. **Инвариант** — зелёная строка «Сумма на счетах 10 000 ₽ — не изменилась ✔»
   либо красная тревога, если сумма поменялась.
6. **Одна из трёх панелей** — «Потоки», «Таймлайн», «Журнал» (по одной за раз,
   как и просили не перегружать экран). Карточка потока по нажатию включает
   фильтр журнала по этому потоку.
7. **Управление**: ▶ Запустить / ⏸ Пауза / ⟲ Сброс.

Сценарий показа для защиты:

1. Пример 2, Сценарий **STM**, темп **показ** — медленно видны зелёные монетки,
   инвариант держится.
2. Темп **нагрузка** — откатов становится много, но сумма на счетах всё равно
   неизменна (ради этого и переигрываются транзакции).
3. Сценарий **Блокировки** — монетки летят медленнее, на счетах появляется «ждёт»,
   зато откатов почти нет: пессимистичный подход платит ожиданием.
4. Сценарий **Без синхронизации** — инвариант краснеет: часть переводов потерялась.
5. Пример 1, **CAS-цикл** — то же для зачислений на один счёт; видно, что
   потерянных пополнений нет, потому что каждая попытка подтверждается
   `CompareExchange`.

## Из чего состоит проект

```
TmLab/
  Models/
    Account.cs          счёт: значение, версия данных, замок, CompareExchange
    TxContext.cs        мини-STM: журнал чтения/записи, валидация, откат, повтор
    Bank.cs             набор счетов и инвариант (сумма денег)
  Simulation/
    SimulationOptions.cs  параметры и готовые темпы показа
    WorkerEvent.cs        событие потока (для очереди в UI)
    SimulationRunner.cs   потоки Task + все четыре сценария синхронизации
  Drawing/
    NetworkDrawable.cs    схема: счета, потоки, летящие монетки
    TimelineDrawable.cs   таймлайн: фазы чтение→вычисление→валидация→коммит
  Views/
    MainPage.xaml(.cs)    экран целиком: разметка и разбор событий
  Platforms/              Android, iOS, Mac Catalyst, Windows
```

Что где искать на защите:

* Пример 1 (CAS) — `SimulationRunner.DepositOnce`, ветка по умолчанию:
  `while (!token.IsCancellationRequested) { ... TryCompareExchange ... }`.
* Пример 2 (транзакция) — `SimulationRunner.TransferStm` и `TxContext.Execute`.
* Валидация версий и неделимость фиксации — `TxContext.Validate` + `CommitGate`.
* Почему сломанный режим действительно ломается — `Account.SetBalanceUnsafe`
  (не публикует версию, поэтому транзакции его «не видят»).

## Как потоки общаются с интерфейсом

Потоки ничего не рисуют и не трогают элементы управления. Правило простое:

```
поток симуляции ──► ConcurrentQueue<WorkerEvent> ──► таймер 40 мс ──► рисование
```

`SimulationRunner` кладёт события (`OpBegin`, `Read`, `Write`, `Validate`,
`Commit`, `Conflict`, `Wait`, `Refused`, `Idle`) в очередь `ConcurrentQueue`,
а страница раз в 40 мс забирает их пачкой, переводит в фазы таймлайна, монетки,
подписи и строки журнала. Поэтому интерфейс не «дёргается» и не требует
блокировок: всё, что видно на экране, обновляется в одном UI-потоке.

Пауза устроена так же аккуратно: `SimulationRunner.Paused` останавливает
потоки на ближайшей проверке, состояние счетов при этом сохраняется —
«Продолжить» возвращает систему в работу с того же места.
